🔴 KOD KALİTESİ & TEMİZLİK (P0 - QUICK WINS)
================================================================================
Hızlıca tamamlanabilecek, kod kalitesini artıracak işler.

1. **[P0-1] System.out.println → Slf4j Logger** ✅
   - **Sorun:** Bazı yerlerde hala `System.out.println` kullanılıyor olabilir.
   - **Çözüm:** Tüm print statement'ları `@Slf4j` + `log.info/debug/error` ile değiştirilmeli.
   - **Komut:** `grep -r "System.out" src/` ile tespit
   - **Önem:** Log aggregation (ELK) için kritik.

2. **[P0-2] Unused Imports & Dead Code Temizliği** ✅
   - **Hedef:** IDE warning'lerinin sıfırlanması.
   - **Araç:** IntelliJ "Optimize Imports" + "Inspect Code"
   - **Kapsam:** Tüm Java dosyaları

3. **[P0-3] Null Safety Audit** ✅
   - **Hedef:** `Optional<T>` kullanımının tutarlılığı.
   - **Kontrol Noktaları:**
     - Service layer return types
     - Repository `findBy*` methods
     - DTO field validations
   - **Araç:** NullAway veya manuel review

================================================================================
🔴 GÜVENLİK (P0 - KRİTİK)
================================================================================
Production öncesi mutlaka tamamlanması gereken güvenlik önlemleri.

4. **[P0-4] Actuator Endpoint Security** ✅
   - **Sorun:** Actuator endpoint'leri production'da açık kalmamalı.
   - **Mevcut Durum:** `ActuatorSecurityConfig.java`'da `permitAll()` var.
   - **Çözüm (application-prod.properties):**
     ```properties
     # Sadece health endpoint açık
     management.endpoints.web.exposure.include=health,info
     management.endpoint.health.show-details=never
     ```
   - **Alternatif:** IP whitelist veya Basic Auth

5. **[P0-5] Sensitive Data Logging Maskeleme** ✅
   - **Sorun:** Log'larda email, token gibi bilgiler görünebilir.
   - **Çözüm:** Custom Logback pattern veya Masking utility
   - **Örnek:**
     ```java
     log.info("User login: {}", maskEmail(email));
     // john.doe@example.com → j***e@example.com
     ```
   - **Kapsam:** AuthController, UserService, PaymentService

6. **[P0-6] Input Validation Audit** ✅
   - **Hedef:** Tüm endpoint'lerde `@Valid` annotation kontrolü.
   - **Kontrol:** DTO'larda `@NotNull`, `@Size`, `@Email` vb.
   - **Riskli Alanlar:** Order notes, address fields, search queries

================================================================================
🚀 ÖZELLİK GELİŞTİRMELERİ (P1 - YÜKSEK ÖNCELİK)
================================================================================
Frontend entegrasyonu için gerekli yeni özellikler.

7. **[P1-1] Real-Time Özellikler (Socket.IO)** ✅
   - **Hedef:** Sipariş durum değişikliklerini anlık bildirmek.
   - **Kütüphane:** `netty-socketio` (v2.0.3)
   - **Port:** `9092`
   - **Events:**
     - `order_created` → Admin odasına
     - `order_updated` → Müşteriye (UUID ile)
   - **Entegrasyon Noktası:** `OrderServiceImpl.updateOrderStatus()`

8. **[P1-2] İptal ve İade (Cancel/Refund)** ✅
   - **Endpoint:** `POST /api/payment/{paymentId}/refund`
   - **Akıllı İade Mantığı:**
     1. Önce Cancel/Void dene (Gün içi işlemler - Komisyonsuz)
     2. "Settlement already done" hatası → Refund'a düş (Komisyonlu)
   - **İş Kuralları:**
     - İptal Edilebilir: `PENDING`, `APPROVED`, `PREPARING`
     - Sadece Admin: `SHIPPING`, `DELIVERED`
   - **Iyzico Methods:** `Cancel.create()`, `Refund.create()`

9. **[P1-3] Elasticsearch Autocomplete**
   - **Endpoint:** `GET /api/search/suggestions?q={query}`
   - **Özellikler:**
     - Fuzzy search (hatalı yazım toleransı)
     - Minimum 2 karakter
     - Max 10 öneri
   - **Response:**
     ```json
     {
       "suggestions": ["Pizza Margherita", "Pizza Pepperoni", ...]
     }
     ```

🟡 KOD TUTARLILIĞI (P2)
================================================================================
Kod kalitesini ve maintainability'yi artıracak refactoring'ler.

10. **[P2-1] Response DTO Standardization**
    - **Hedef:** Tüm endpoint'ler aynı wrapper format kullanmalı.
    - **Öneri:**
      ```java
      public class ApiResponse<T> {
          private boolean success;
          private T data;
          private String message;
          private LocalDateTime timestamp;
      }
      ```
    - **Kapsam:** Tüm Controller'lar

11. **[P2-2] Pagination Response Tutarlılığı**
    - **Sorun:** Bazı yerlerde `Page<T>`, bazı yerlerde custom DTO.
    - **Çözüm:** Tek bir `PagedResponse<T>` DTO'su
    - **Alanlar:** `content`, `page`, `size`, `totalElements`, `totalPages`, `last`

12. **[P2-3] Exception Hierarchy Review**
    - **Hedef:** Custom exception'ların tutarlılığı.
    - **Kontrol:** Tüm exception'lar `ApiException`'dan extend edilmeli.
    - **HTTP Status mapping review**

================================================================================

13. **[FINAL-1] API Versioning**
    - **Hedef:** `/api/v1/` prefix stratejisi
    - **Yöntem:** URL path versioning
    - **Backward Compatibility:** Eski endpoint'ler deprecate edilmeli

14. **[FINAL-2] OpenAPI/Swagger Enhancement**
    - **Hedef:** Tüm endpoint'lere detaylı Swagger annotations
    - **Kapsam:**
      - `@Operation` descriptions
      - `@ApiResponse` examples
      - `@Schema` DTO documentation
    - **Çıktı:** Otomatik API dokümantasyonu

15. **[FINAL-3] Structured Logging (ELK Ready)**
    - **Hedef:** JSON format logging
    - **Kütüphane:** Logback JSON encoder
    - **Eklenecekler:**
      - Correlation ID (request tracking)
      - User ID in MDC
      - Request/Response timing
